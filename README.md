# Warcraft III: от lockstep к клиент-серверной архитектуре

Самостоятельный проект по изменению сетевой архитектуры Warcraft III.
**Главная цель — лишить мапхак доступа к скрытому текущему состоянию матча,
сохранив сам Warcraft и совместимость старых кастомных карт.**

Целевая модель: сервер определяет состояние игрового мира и результаты
действий, а клиент получает только разрешённые ему сведения. Требуется
сохранить привычные отображение, интерфейс, звук и управление.
**Архитектуру проектируем заново.** Прежняя схема не принята за основу;
способ исполнения движка, скриптов и клиента ещё предстоит определить.
Первая исследуемая версия — **Warcraft III 1.26a, build 6401**; поддержка
других сборок потребует отдельных контрактов и проверок.

Репозиторий: [DinCrAsh-code/war3-client-server](https://github.com/DinCrAsh-code/war3-client-server).

## Что значит «победить мапхак»

В lockstep клиенты воспроизводят полный мир по общим действиям. Скрытие
объекта на экране не устраняет его состояние из клиентской симуляции.
Наш принцип: запрещённые игроку данные не должны попадать на его компьютер.
Проверяется весь путь — сетевые сообщения, память, миникарта, эффекты, звук,
интерфейс, реконнект и наблюдение.

Ранее увиденные сведения нельзя заставить клиента забыть. Данные, которые
сама карта разрешает раскрывать, остаются разрешёнными. Автоматизация ввода
и обмен информацией между игроками — отдельные угрозы.

## Что уже есть

На **2026-09-25** здесь подготовлены описание проекта, архитектурные
требования, обзор исследованных контрактов движка и план проверки.
Реализации сервера, клиента и сетевого протокола пока нет.
Изученные материалы подтверждают ограниченные эксперименты с движком,
но не готовый матч, headless-сервер или совместимость всех карт.

Текущие требования определяются актуальными Markdown-документами.
[Исторические схемы и разбор](docs/archive/2026-09-25-initial/README.md)
сохранены для происхождения идеи. Их числа, сроки и подписи «пройдено»
не являются текущей приёмкой. Кодовые каталоги добавляются вместе с первой
реализацией; пустых каркасов компонентов здесь пока нет.

## Ближайшая проверяемая цель

Восстановить зависимости одного игрового действия: ввод → приказ → изменение
мира → скриптовые события → разрешённые сведения → UI. На этой основе
проверить варианты разделения исполнения, особенно локальный JASS и
зависимость интерфейса от полного мира. Затем выбрать новую архитектуру
и построить короткую сессию для двух игроков.

Исходные игровые файлы, карты, дампы и закрытые исследовательские артефакты
в репозиторий не входят. Сведения о движке изложены отдельно от кода других
продуктов; зависимости на их реализацию здесь нет.
