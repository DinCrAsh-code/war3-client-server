# Совместимость Warcraft и старых карт

Обязательное требование проекта: сохранить привычную игру и поведение
существующих карт при смене сетевой архитектуры. На 2026-09-25 ни одна карта
не прошла приёмку в новой архитектуре — реализации ещё нет.

## Что считаем совместимостью

Совместимость означает совпадение наблюдаемой механики и разрешённого UI
при одинаковых входах, версии движка и карты. Совпадение названия карты,
успешная загрузка или одинаковый `Game.dll` этого не доказывают.

Базовая цель — запуск старой карты без изменения её файла. Если нужен
адаптер или специальная сборка расширения, это отдельный статус, не
прозрачная совместимость. Поддержка карт не равна сетевой совместимости
обычного клиента с новой партией: для неё нужен адаптер клиента.

## Матрица обязательного покрытия

| Область | Что сохранить и проверить |
|---|---|
| Загрузка | Рельеф, pathing, объекты, данные и ресурсы карты; порядок config/main |
| Симуляция | Приказы, очереди, способности, бой, экономика, AI, коллизии и движение |
| Время и RNG | Игровые часы, паузы, скорости, порядок таймеров/событий, startup seed и потребление RNG |
| JASS | Типы, handles, lifetime, события, таймеры, ожидания и продолжения |
| Локальный контекст | `GetLocalPlayer`, камера, выделение, локальные значения и адресные сообщения |
| Презентация | Панель команд, инвентарь, tooltips, миникарта, анимация, звук, эффекты, диалоги |
| Туман | День/ночь, высоты, общий обзор, альянсы, fog modifiers, невидимость и детект |
| Пользовательские данные | GameCache, предусмотренная картой синхронизация и сохранение; нельзя молча отключить |
| Нативные расширения | Точная версия PE, обращения к UI, времени, потокам, локальному игроку и памяти |
| Сессия | Выход игрока, пауза, завершение, реконнект и права наблюдателя |
| Обычный Warcraft | Запуск и игра без нового режима, пользовательские настройки и целостность установки |

Это план покрытия, не список уже реализованных возможностей.

## Главная граница: локальные скрипты

Локальные значения могут использоваться после ветки `GetLocalPlayer`,
сохраняться в глобалах или продолжениях после ожидания. Простая подстановка
номера игрока и повтор всего скрипта способна повторить общие игровые эффекты.
Простое удаление локальных веток ломает интерфейс и поведение карты.

Нужно определить авторитетный общий контекст, персональные контексты,
границы чтения и записи, идентичность handles и доставку событий.
Общие игровые эффекты выполняются ровно один раз; персональные данные
доставляются правильному адресату. Камера и локальное выделение не должны
становиться доверенным источником серверной истины.

Способ разделения ещё не выбран. Первые тесты обязаны включать локальное
значение, используемое за пределами ветки, и продолжение после ожидания.

## Карты с нативным кодом

Совместимость обычного JASS не доказывает совместимость карты с PE-расширением.
Для каждого расширения нужны fingerprint и проверка зависимостей от конкретной
сборки движка, рендера, ввода и локального контекста. Если необходим server mode,
его поддержка обсуждается с владельцами исходников расширения и проверяется
отдельно. Формулировка «работает как есть» до этого недопустима.

## Совместимость и раскрытие информации

Если карта по правилам показывает данные обо всех игроках, это законное
раскрытие. Запрет такого UI меняет карту. Если её реализация требует на
клиенте полный секретный мир, нужен другой способ сохранить наблюдаемое
поведение; передача этого мира не становится допустимой мерой совместимости.

Неразрешимый в текущем адаптере случай фиксируется как неподдержанный,
с точной причиной и следующим исследованием. Цель поддержки не снимается.

## Карточка проверки версии карты

Для каждой включённой в корпус карты записывать ID/версию и SHA-256,
сборку движка, расширения, исходные условия, сценарии, ожидаемое поведение,
отчёт проверки и оставшиеся ограничения. Сам файл карты хранить вне Git.

Допустимые статусы:

- `not-tested` — не проверена в новой архитектуре.
- `compatible` — пройдены заявленные сценарии без изменения карты.
- `compatible-with-adapter` — пройдены сценарии с явно названным адаптером.
- `blocked` — есть воспроизводимое препятствие; указаны находка и причина.
- `regression` — прежде пройденный сценарий теперь нарушен.

Статус относится только к перечисленному покрытию. Нельзя переносить его
на все версии карты или на все кастомки по одному успешному матчу.

## Сохранность установки

Новый режим подключается обратимо: исходные файлы игры и карты не
перезаписываются, настройки не теряются. После нормального выхода и после
сбоя можно запустить обычный Warcraft. Перед обновлением адаптера проверяются
версия и fingerprint; неизвестная сборка получает понятный отказ.
Политика распространения игры и её ресурсов не меняется этим документом.
