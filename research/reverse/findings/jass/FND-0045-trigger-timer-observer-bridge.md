## Вывод

Косвенный мост из [FND-0041](FND-0041-trigger-action-continuation.md) имеет конкретные стороны: `CTriggerExecution+0x34` — встроенный `CAgentTimerExtended`; его arm-слот создаёт timer event и через проверяющее присваивание сохраняет ref на owner `CTriggerExecution`, если тот проходит проверку. Fire-слот при допустимом состоянии вызывает observer-слот `+0x0C` сохранённого owner. Для обычного `TriggerSleepAction` через этот путь передаётся **event code `0`**, который в `CTriggerExecution` выпускает `ResumeTriggerExec`. Event code `1` ведёт к иной проверке таймера/звука; прежнее отождествление sleep с case `1` отвергнуто. Фактическая доставка события из очереди и время пробуждения остаются за пределами статических function-записей.

[Vtable `CTriggerExecution`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/classes/0x6F950C14.json) связывает observer slot `+0x0C` с `0x6F446DA0`.
2. На статусе sleep `3` [`0x6F4442D0`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F4442D0.json) передаёт duration из JASS instance и аргументы `eventId=0`, `owner=trigger`, `extra=0`, `clockFlag=1` в [`0x6F477A80`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F477A80.json). Эта обвязка вызывает виртуальный slot `+0x08` embedded timer. Его конкретное тело [`0x6F4781F0`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F4781F0.json) при уже активном `timer+0x0C` сначала отменяет старую запись, затем подготавливает время, вызывает [`0x6F477F80`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F477F80.json) для новой timer-записи и присваивает owner в `timer+0x08` через проверяющий ref-assign [`0x6F022AA0`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F022AA0.json). Это прямая регистрация адресата с учётом refcount; отдельная подписка owner в список здесь не требуется.
3. [`0x6F477F80`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F477F80.json) передаёт eventId в [`0x6F477EF0`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F477EF0.json), который кладёт его в timer-event `+0x1C`. При входе в fire-слот [`0x6F4780A0`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F4780A0.json) переносит это поле в message `+0x08`, удерживает owner из `timer+0x08` локальным ref и, если глобальный game gate `+0x08` ненулевой и owner существует, вызывает у owner vtable slot `+0x0C`. По двум vtable выше цель — [`CTriggerExecution::0x6F446DA0`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F446DA0.json).
4. Положительный контроль для обычного сна: `eventId=0` из `0x6F4442D0` попадает в `0x6F446DA0` case `0`, который отправляет команду через [`0x6F43F620`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F43F620.json); её проверки handle/token описаны в [FND-0044](FND-0044-trigger-continuation-command-identity.md). Перед switch observer разрешает пару `trigger+0x0C/+0x10` через `0x6F03FA30` и возвращает без отправки, если объект не найден, его поле `+0x0C` равно `0x2B61676C` либо `+0x20` ненулевое. Отрицательный контроль: message code `1` ведёт в [`0x6F445870`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F445870.json) с проверкой отдельного `trigger+0x94`; к обычному `TriggerSleepAction` этот case не следует приписывать. При нулевом owner либо закрытом game gate fire-слот не вызывает observer.
5. [`0x6F477D30`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F477D30.json) отменяет/отцепляет активный timer event: при нужном состоянии ставит event-флаг `0x10000`, очищает `timer+0x0C`, снимает ref с owner `timer+0x08` и очищает управляющие bits `0x02/0x04`. Для однократного события (`extra=0` из `0x6F4442D0`) fire-слот вызывает эту отмену до observer call, удержав собственный локальный ref. [Деструктор `CTriggerExecution`, `0x6F4460F0`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F4460F0.json) вызывает [`0x6F477E90`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F477E90.json) для embedded timer; тот тоже вызывает `0x6F477D30`. Это отрицательный контроль маршрута отзыва.

## Ограничения и отвергнутые гипотезы

Исследован контракт передачи owner/eventId и условного fire-слота, а не динамический прогон таймерной очереди. Вызов fire-слота из очереди, точность задержки, гонка cancel/fire, все clock режимы и произвольная длительность сна не проверены. Статический код отмены показывает флаги и refcount, но не доказывает, что уже помещённый в очередь callback никогда не дойдёт до fire; решение зависит от обработки флага очередью. Значение game gate `global+0x08` не переименовано без анализа его владельца. `S10 CEventAnnouncer::PostEvent` — имя обвязки; конкретный arm/fire здесь установлен по S11-vtable, а не по одному этому имени.

## Значение для проекта

Продолжение после сна требует не только JASS cursor и token команды, но и жизненного цикла timer/owner: замена ожидания отменяет старое событие, однократный fire снимает timer-ref, уничтожение execution также отменяет событие. Следующий контроль — динамически сопоставить поставленный event, его fire и отмену с исходами `ResumeTriggerExec`, включая старый callback после отмены. Без этого нельзя обещать корректную семантику сна при разделении скриптов по игрокам.
