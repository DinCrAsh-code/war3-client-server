## Вывод

В маршруте trigger action код `3` от JASS VM ведёт к сохранению ключа JASS instance и текущего action, чтению длительности из instance и **публикации** события с этим значением. Для объекта `CTriggerExecution` найден путь окончания ожидания: event callback проверяет таймер и выпускает команду `ResumeTriggerExec` (`0xA0062`), её обработчик проверяет trigger handle и token и повторно вызывает обход действий. Сохранённый instance может исполняться от своего opcode cursor. Код `4` (`TriggerSyncStart`) идёт по другой ветке; обычное завершение освобождает ключ. Связь конкретной публикации с callback всё ещё проходит через косвенный dispatch.

## Основание и контроли

1. [`0x6F447340`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F447340.json) перебирает список действий и вызывает [`0x6F445800`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F445800.json) → [`0x6F3BA890`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F3BA890.json) → [`0x6F3A8340`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F3A8340.json). При обработке ожидания trigger `+0x50` держит ключ JASS instance, а `+0x54` — указатель ожидающего action. При последующем проходе `+0x54` фильтрует список до этого action.
2. `0x6F3A8340` создаёт instance, только когда ячейка ключа пуста, затем вызывает [`0x6F44B6A0`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F44B6A0.json) → [`0x6F45FA30`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F45FA30.json). Статусы `1`, `2`, `6` вызывают освобождение key и обнуляют ячейку; `3` и `4` этой очистки не делают. Положительный контроль: это не повторное создание instance после каждого yield.
3. В `0x6F45FA30` прежний cursor instance `+0x20` сохраняется во внутреннем стеке. Если cursor не нулевой и переданный флаг `arg_14=0`, управление сразу идёт к `0x6F45FBFB` и далее к [`ExecuteOpcodeStream`, 0x6F45E9D0](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F45E9D0.json) с этим cursor. В `0x6F447340` флаг `arg_14` для этого вызова равен нулю, когда `trigger+0x54` уже удерживает action; это статическое условие пути возобновления. При нулевом cursor или ненулевом флаге `0x6F45FA30` выбирает другую ветку начального исполнения.
4. На коде `3` `0x6F447340` читает sleep kind из instance `+0x38` через [`0x6F44B320`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F44B320.json). Для `TriggerSleepAction` он равен нулю ([FND-0040](FND-0040-jass-vm-yield-status.md)), поэтому выбирается путь с `trigger+0x54=action`. [`0x6F44B3C0`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F44B3C0.json) читает длительность instance `+0x40`; [`0x6F4442D0`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F4442D0.json) передаёт её в [`0x6F477A80`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F477A80.json) от embedded announcer `trigger+0x34` с owner=trigger. В [S10](../../../../src/Misc/eventannouncer.h) `0x6F477A80` представлен как `CEventAnnouncer::PostEvent`, публикация подписчикам через vtable, а не реализация очереди времени.
5. [Конструктор `0x6F446010`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F446010.json) ставит vtable `CTriggerExecution` на объект и отдельную `CAgentTimerExtended` на его подобъект `+0x34`. [Vtable `CTriggerExecution`, `0x6F950C14`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/classes/0x6F950C14.json) связывает event slot `+0x0C` с [`0x6F446DA0`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F446DA0.json). В его event case `1` вызывается [`0x6F445870`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F445870.json). По ветке окончания ожидания он освобождает timer/reference state и вызывает [`0x6F43F620`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F43F620.json) с token `trigger+0x90`. Эта функция конструирует `CNetCommandResumeTriggerExec` с типом `0xA0062` и отправляет его в командный путь. [S10 описывает тот же тип и приём полей команды](../../../../src/Net/netcommand_classes_multifield.h), но не заменяет проверку её доставки.
6. [`0x6F440DB0`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F440DB0.json) и [`0x6F440F70`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F440F70.json) регистрируют обработчик команды `0x62`: [`0x6F440620`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F440620.json). Он разрешает trigger handle, проверяет тип и незавершённость и вызывает [`0x6F447700`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F447700.json) с token. Последний сравнивает token с `trigger+0x90`, при совпадении увеличивает `+0x90` на 1 и лишь затем вызывает `0x6F447340`. Это положительный контроль условного повторного входа; несовпавший token и недействительный handle — отрицательные контроли.
7. Отрицательный контроль для ожидания: статус `4` в `0x6F447340` проходит через `0x6F447423` и `0x6F4442D0` с нулевым флагом публикации sleep-события, после чего вызывает `0x6F43F620` по отдельному маршруту синхронизации; подменять им статус `3` нельзя. Код `1` в `0x6F3A8340` освобождает instance и обнуляет key, то есть сохранение key ограничено незавершённым исполнением.

## Ограничения и отвергнутые гипотезы

Это чтение S11, не запуск DLL и не проверка одного полного матча. `0x6F477A80` использует виртуальный вызов; точная связка этой публикации с observer callback `0x6F446DA0`, условия постановки в очередь, время пробуждения и отмена события требуют отдельной проверки. Между отправкой `ResumeTriggerExec` и обработчиком есть сетевой командный путь: статическая карта типов не доказывает доставку в каждом сценарии. `TriggerExecuteWait`, иные sleep kind, ошибки и завершение trigger требуют своих контролей. Здесь нет доказательства, что локальный ввод до сна превращается только в персональный эффект после него.

## Значение для проекта

Совместимость JASS требует удержать именно экземпляр, его cursor, текущий action и семантику отложенного повторного входа через команду `0x62`. Решение о разделении локального и общего исполнения нельзя принимать только по телам отдельных нативов. Следующая проверка: подтвердить dispatch от announcer к observer и поведение команды в матче, затем воспроизвести короткий скрипт с разным локальным вводом до `TriggerSleepAction` и наблюдением общего и персонального эффектов после пробуждения.
