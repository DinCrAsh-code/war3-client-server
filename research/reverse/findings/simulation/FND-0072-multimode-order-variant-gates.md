## Внешние и внутренние режимы

[`0x6F373FE0`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F373FE0.json)
сначала берёт первый объект локального selection через `0x6F421E50`.
Без него показанный путь возвращает `0`. Входной режим из второго
stack-аргумента (`arg_4` до повторного использования IDA-слота)
разделяет три ветви: `4` вызывает отдельный `0x6F2FB920` и отвечает
`1`; `2` идёт в иной путь через `0x6F3783E0/0x6F3793F0`; только `1`
достигает разобранного ниже выбора сетевых вариантов. Для режима `1`
нужны разрешённая ссылка на target и `target+0x20 & 4`; иначе ранний
выход. Значения этих входных режимов не названы игровыми действиями,
поскольку caller и runtime эффект здесь не установлены.

Позиция берётся либо из дополнительного входного указателя `arg_8`
(`+0x1C`), либо из virtual `+0xE0` цели. В этом entry
[`0x6F2AD5D0`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F2AD5D0.json)
вызывается **только при ненулевом дополнительном указателе**; при его
отсутствии локальный результат для выбора варианта принудительно `0`.
Шестипольный descriptor цели всё равно строится через `0x6F261E20`,
но в показанном финальном выборе используется лишь при положительном
локальном результате. Это добавляет guard к связи fog bit → wire ID из
[FND-0070](FND-0070-point-target-route-selected-unit-visibility.md).

После общих flags функция выбирает ветвь по `record+0x14 & 0x3FF`.
Указанные ниже вызовы происходят при прохождении соответствующих
предварительных проверок `0x6F335xxx/0x6F336xxx`, а не безусловно:

| Значение | Проверяемый маршрут после предварительного ответа `0` | Возможная отправка |
|---|---|---|
| `4` или `6` | При положительном локальном результате предварительный `0x6F336090` получает descriptor; иначе `0x6F335FD0` получает target | `0x6F339F80` → `0xA0014` при положительном результате; `0x6F339DD0` → `0xA0012` при нуле |
| `2` | `0x6F335F80` проверяет point-кандидата | `0x6F339CC0` → `0xA0011`; сюда же может попасть fallback из прежней ветви с ответом `0xDD`, где вместо point возможен `0x6F339DD0` |
| `256` | `0x6F3360C0` получает descriptor при положительном результате, иначе `0x6F336040` получает target; при некоторых ненулевых ответах идёт ещё `0x6F336000` | `0x6F33A010` → `0xA0015`, только если положительный результат и target сохранён; иначе `0x6F339E60` → `0xA0013` |

Соответствие wrappers wire ID проверено по
[FND-0069](FND-0069-outbound-point-target-fogged-order-builders.md).
В этой второй семье вариантов положительный локальный predicate снова
выбирает класс с именем `Fogged` (`0xA0014/15`), а не доказывает, что
цель скрыта. `0xA0014/15` здесь не означают один и тот же payload:
`0xA0015` добавляет вторую identity к descriptor.

## Отрицательные ветви и границы

Ненулевой ответ предварительной проверки может перейти в сообщение
об ошибке `0x6F2F8C30` либо в дополнительную попытку; это не тот же
путь, что непосредственный вызов wrapper. Показанная функция затем
может вернуть `1` и после этой обработки. Поэтому её return `1`
**не является доказательством**, что приказ попал в turn store или к
peer. При нулевом selection, неподходящем target, другом входном
режиме либо недопустимом значении `record+0x14 & 0x3FF` результат
или действие иные.

Положительный статический контроль: входной режим `1`, допустимый
target, выбранный объект, дополнительный указатель, положительный
локальный predicate и нулевой предварительный ответ дают fogged
wrapper для ветвей `4/6` или `256`. Отрицательный контроль: без
дополнительного указателя локальный результат равен `0`; при тех же
допусках выбираются прямые target варианты. Возможные внутренние
fallback на ответ `0xDD/0x57` отделены от этого контроля.

Для авторитетного сервера надо проверять режим, право выбранного юнита,
допустимую цель и descriptor после получения команды; client-side
выбор wire ID и возвращаемое значение не могут заменить эти проверки.
Следующий опыт — один и тот же приказ с видимой/скрытой/устаревшей
целью и с/без дополнительного указателя: отдельно снять предварительный
ответ, wire ID, очередь turn store и фактическую task.
