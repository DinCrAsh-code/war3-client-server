## Допуск к локальной очереди

Сетевой normal-path того же `0x6F54D970` уже описан в
[FND-0066](https://github.com/DinCrAsh-code/war3-client-server/blob/83bc16bee5252f67c8ae22d913777d30407f2f10/research/reverse/findings/network/FND-0066-online-turn-store-flush-boundary.md)
другого PR. Здесь он сверен для семейства приказов и связан с
пятью исходящими сериализаторами из [FND-0073](FND-0073-order-payload-writer-chain.md),
которые
передают готовый буфер и индекс игрока в
[`0x6F54D970`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F54D970.json).
Функция берёт контекст из TLS-слота `0x0D`, следует по указателям
`+0x10` и `+0x08` к записи сессии и возвращается без чтения буфера,
если переданный индекс не равен `session+0x610` либо состояние записи
`session+0x278+index*0x304` меньше `3`. Индекс используется после
этого сравнения; сам по себе этот код не доказывает безопасную обработку
произвольного индекса или его связь с удалённым peer.

Через vtable-слот `+0x24` входного буфера запрашиваются указатель на
байты и их размер. Нулевой размер отбрасывается. Только при индексе `0`
и ненулевом глобальном указателе мира функция получает действующий слот
из `world+0x28`, запись через `0x6F3A1650` и вызывает `0x6F545270`
с первым байтом команды. Ненулевой результат этого вызова отбрасывает
команду. При других условиях эта проверка не вызывается; она не
заменяет проверку авторизации игрока на сервере.

Остаток вычисляется как `writePos(+0x1C88) - readPos(+0x2244) + size`.
Если он не меньше `0x400`, вызывается
[`0x6F54D930`](https://github.com/FilippTheBestDev/claudecraft/blob/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/funcs/0x6F54D930.json),
после чего остаток вычисляется заново. Только значение строго меньше
`0x400` доходит до `0x6F4C25A0` (`WriteRaw`) для очереди `session+0x1C78`.
Ветка повторного отказа зовёт `nullsub_1` с диагностическими
аргументами; она не записывает буфер.

`0x6F54D930` сравнивает тег `session+0x2288` с `LOOP` (`0x4C4F4F50`)
и `NONE` (`0x4E4F4E45`). Для этих тегов управление передаётся
`0x6F54D760`, разобранный отдельно в [FND-0075](FND-0075-special-order-queue-record.md).
В обычной ветви
вызывается `0x6F650480` на очереди `+0x1C78`, затем её vtable-слот
`+0x1C`. Это граница локальной очереди, не доказательство сетевой
доставки, обработки другим участником или правильного решения о
раскрытии скрытого состояния.

## Контроли и следующий вопрос

Положительный статический контроль: совпадающий активный индекс,
состояние `>=3`, ненулевой размер и остаток `<0x400` проходят к
`WriteRaw`, если условный фильтр первого байта не отверг запись.
Отрицательные ветви: несовпадающий индекс, состояние `<3`, пустой
буфер и повторный остаток `>=0x400` не вызывают `WriteRaw`; ненулевой
результат `0x6F545270` отбрасывает команду только в описанном режиме.

Следует проследить обычную очередь после vtable-слота `+0x1C` и
путь записи `0x1F` из [FND-0075](FND-0075-special-order-queue-record.md),
связь индекса с действительным отправителем и фактическую
доставку на двух игроках. Для варианта со скрытой целью нужно отдельно
сравнить сериализованный descriptor, допуск к очереди и содержимое,
доступное получателю.
