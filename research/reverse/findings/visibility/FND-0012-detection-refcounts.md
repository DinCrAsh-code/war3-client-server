## Вывод

Разрешённый объект по ссылке юнита `+0x130` содержит два независимых набора
счётчиков, индексируемых игроком: `+0x2C + 4*i` и `+0x74 + 4*i`.
`CUnit::QueryDetection` (`0x6F27A320`, в S11 `EXACT`) при флаге `1`
проверяет ненулевой счётчик первого набора, при флаге `2` — второго и
возвращает логическое ИЛИ. При неразрешённой ссылке возвращает `0`.
Назначение каналов пока не установлено; называть один из них «обычным»
или «истинным» зрением было бы догадкой.

`0x6F27A240` увеличивает выбранные флагами счётчики и выставляет бит
игрока в словах `+0x24`/`+0x6C` при переходе счётчика `0 → 1`.
`0x6F27A2B0` уменьшает их и снимает соответствующий бит при `1 → 0`.
Короткая пара `0x6F27A3C0`/`0x6F27A400` меняет только первый канал.
Следовательно, серверной политике выдачи нельзя заменить этот слой одним
постоянным boolean на юнит: источники эффекта могут перекрываться и
отзываться по отдельности.

## Связь с источниками эффекта

Статический путь от именованных RTTI-классов уже прослеживается без
повторного обхода всех унаследованных vtable-слотов:

- `CAbilityDetector` через `0x6F0551D0` → `0x6F046CA0` →
  `0x6F296680` → `0x6F27A240` добавляет выбранный канал; через
  `0x6F054EB0` → `0x6F284A50` → `0x6F27A2B0` существует путь снятия.
- `CBuffDetected` через `0x6F0D3680` → `0x6F296680` добавляет эффект,
  а через `0x6F0D5190` → `0x6F284A50` снимает его.
- `CBuffSharedVision` дополнительно использует `0x6F2967F0` →
  `0x6F27A3C0` для добавления первого канала и `0x6F28DC80` →
  `0x6F27A400` для его снятия. Точная семантика условий и порядка
  этих вызовов открыта.

Основание для имён классов — [vtable-записи](https://github.com/FilippTheBestDev/claudecraft/tree/10950d496aa7357a6180c1956def50c2a3e8c1a9/agent_worktrees/classes),
а не имя, выведенное из поведения функций. В таблице ниже указан текущий

## Контроли, пределы и следующий опыт

Положительный статический контроль: флаг `1` проходит через `+0x2C`,
флаг `2` через `+0x74`; `0 → 1` и `1 → 0` меняют соответствующий бит.
Отрицательные контроли: `QueryDetection` с флагами `0` не читает ни один
счётчик и возвращает `0`; при неразрешённой ссылке — тоже `0`. Удаление
`0x6F27A2B0` при неположительном выбранном счётчике возвращает `0`.
Если выбраны оба канала, этот путь может успеть уменьшить первый до отказа
по второму: атомарность снятия из IDA-потока не следует.

Собственного запуска, сравнения с исходным Game.dll и измерения событий
обновления масок нет. Границы допустимого `i`, смысл флагов, происхождение
каждого добавления и то, какие сведения получает клиент при детекте без
обзора, не доказаны. Само имя `CBuffSharedVision` не превращает детект в
полную видимость юнита. Следующий ограниченный опыт — для двух игроков
добавить два перекрывающихся источника по очереди, снять один, затем второй;
для каждого шага сверить оба счётчика, `QueryDetection`, `IsUnitDetected`,
`IsUnitVisible` и клиентский вывод. Контрольному игроку не давать обзор.
