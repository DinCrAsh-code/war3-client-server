# Общие участки реверса

Этот файл показывает, **какие смысловые участки сейчас исследуются** и где
другим разработчикам увидеть ход работы. Он не заменяет
[индекс проверяемых находок](INDEX.md), [карту технических маршрутов](SRC_MAP.md)
или адресные claims в S11. Сведения о работе других команд появляются
здесь только после их PR; отсутствие строки не означает, что участок свободен.

Параллельные исследователи одного участка публикуют выводы через один
интеграционный PR или связанные PR с явной границей файлов и тем.
Открытый PR и его commits показывают фактический прогресс; строка выше
не резервирует всю подсистему `visibility`.

## Как брать следующий участок

1. Прочитать [ROADMAP](../../docs/ROADMAP.md), [INDEX](INDEX.md),
   [SRC_MAP](SRC_MAP.md) и активные PR. Искать уже записанную находку
   и пересечение по причинному маршруту, а не только по названию функции.
2. В начале работы открыть draft PR с ожидаемым результатом,
   границами пакета, владельцем интеграции, закреплённой ревизией источника,
   способом проверки и ссылками на пересекающиеся PR. Issue можно добавить
   для обсуждения, но интеграция идёт через PR. Добавить сюда строку
   с этим указателем. Для кода в приватном matching pipeline отдельно
   проверять и вести адресные claims через его `worktree_store.py`.
3. Коммитить один доказанный контракт или исправление за раз. Новую
   `FND-NNNN` и строку [INDEX](INDEX.md) добавлять **одним коммитом**;
   статическое чтение помечать `source-reviewed`, собственный опыт —
   `reproduced` только после исполнения. PR обновлять по ходу работы,
   включая отрицательные результаты и непроверенные границы.
4. При завершении или передаче участка обновить строку: что реально
   проверено, где PR/отчёт опыта и какой следующий вопрос. Merge PR не
   означает, что подсистема восстановлена. Архитектурные решения и
   критерии продукта остаются в `docs/`, а не в этом списке.

Следующий приоритет после этих участков выбирается по
[ROADMAP](../../docs/ROADMAP.md), [INDEX](INDEX.md) и текущим PR. Отсутствие
строки не означает, что адреса свободны от работы других команд.
